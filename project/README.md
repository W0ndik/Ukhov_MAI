# Определение болезней пшеницы на снимках с беспилотника

Проект посвящён подготовке датасета для задачи определения признаков жёлтой ржавчины пшеницы на RGB-снимках, полученных с беспилотника.

## Цель работы

Цель работы — выбрать подходящий датасет, выполнить ручную разметку части изображений в Label Studio и подготовить инструкцию для разметчика. Полученная разметка может использоваться как основа для дальнейшего обучения модели компьютерного зрения или подключения ML-backend для автоматической предразметки.

## Используемый датасет

В качестве исходных данных использован открытый датасет **Yellow rust infestation in wheat**, размещённый на платформе Figshare.

Датасет содержит RGB-снимки пшеничного поля, полученные с беспилотника DJI. Изображения подходят для задачи анализа состояния посевов, так как на них видны участки поля с различной окраской, неоднородной плотностью растительности, почвой, тенями и возможными признаками поражения жёлтой ржавчиной.

Для ручной учебной разметки была использована часть датасета — 21 изображение.

## Используемые инструменты

- Label Studio — для ручной разметки изображений;
- Python — для запуска вспомогательных скриптов;
- Pillow — для построения визуализаций разметки;
- JSON-экспорт Label Studio — для сохранения результатов разметки;
- Visual Studio Code / Visual Studio — для работы со структурой проекта.

## Формат разметки

Для разметки выбрана задача **object detection**. Объекты и зоны на изображениях выделяются прямоугольными рамками — bounding boxes.

Такой формат выбран потому, что на снимках с беспилотника видны не отдельные листья, а участки поля. Поэтому разметка выполняется по зонам посева, а не по отдельным растениям.

## Классы разметки

В проекте используются следующие классы:

- **Yellow rust area** — участок с возможными признаками жёлтой ржавчины;
- **Healthy wheat / normal canopy** — визуально здоровый участок посева;
- **Bare soil / ground** — почва, пустой участок или зона без растительности;
- **Unclear / shadow / blur** — спорная, затенённая, размытая или плохо различимая зона.

Ровные светлые полосы на снимках не относились автоматически к заболеванию, так как они могут быть связаны со следами техники, технологическими колеями, междурядьями или особенностями съёмки. Такие участки при отсутствии уверенности относились к классу **Unclear / shadow / blur**.

## Порядок выполнения работы

1. Был выбран открытый датасет со снимками пшеничного поля, полученными с беспилотника.
2. Часть изображений была скопирована в папку `data/images/`.
3. В Label Studio был создан проект для ручной разметки.
4. Для проекта была подготовлена XML-конфигурация интерфейса разметки.
5. Изображения были импортированы в Label Studio.
6. На изображениях были размечены зоны возможной жёлтой ржавчины, здорового посева, почвы и спорных участков.
7. Были сделаны скриншоты процесса разметки.
8. Итоговая разметка была экспортирована в формате JSON.
9. Была подготовлена инструкция для разметчика.
10. Были добавлены скрипты для подсчёта статистики и визуализации разметки.

## Запуск Label Studio

Для запуска проекта необходимо установить зависимости:

```bash
pip install -r requirements.txt
```

После этого можно запустить Label Studio:

```bash
label-studio start
```

После запуска интерфейс будет доступен по адресу:

```text
http://localhost:8080
```

В Label Studio необходимо создать проект, вставить конфигурацию из файла:

```text
label_studio/labeling_config.xml
```

и импортировать изображения из папки:

```text
data/images/
```

## Экспорт разметки

После завершения ручной разметки результат экспортируется из Label Studio в формате JSON.

Файл экспорта находится по пути:

```text
data/exports/project-export.json
```

Этот файл используется для подсчёта статистики и построения визуальных примеров разметки.

## Статистика разметки

Для автоматического подсчёта статистики используется скрипт:

```text
scripts/stats_from_export.py
```

Запуск:

```bash
python scripts/stats_from_export.py
```

Скрипт рассчитывает:

- количество импортированных изображений;
- количество размеченных изображений;
- общее число прямоугольных областей;
- среднее число областей на изображение;
- распределение областей по классам.

Результат сохраняется в файл:

```text
docs/annotation_stats.md
```

## Визуализация разметки

Для построения примеров изображений с наложенными bounding boxes используется скрипт:

```text
scripts/visualize_export.py
```

Запуск:

```bash
python scripts/visualize_export.py
```

Скрипт берёт данные из JSON-экспорта Label Studio, находит соответствующие изображения в папке `data/images/` и сохраняет примеры визуализации в папку:

```text
docs/assets/
```

Примеры визуализации:

```text
docs/assets/example_01.png
docs/assets/example_02.png
docs/assets/example_03.png
```

Эти изображения нужны для быстрой проверки качества разметки без открытия Label Studio.

## ML-backend

ML-backend в рамках проекта является дополнительной частью. В текущей работе основное внимание уделено выбору датасета, ручной разметке изображений, подготовке инструкции и экспорту результата.

После расширения датасета и накопления большего количества размеченных изображений можно обучить модель object detection, например YOLOv8, и подключить её к Label Studio для автоматической предразметки новых снимков.
